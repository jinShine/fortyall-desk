# 1. 이 서비스는 무엇인가 (한 문단)

테니스 레슨장은 수기 장부와 엑셀로 돌아간다. 코치가 장부에 출석을 체크하면 누군가 엑셀로
옮기고, 원장은 엑셀을 보고 잔여 횟수를 답한다. **옮기는 사이에 어긋나고, 어긋나면 회원과
말싸움이 난다.** 이 서비스는 그 옮기는 작업 자체를 없앤다 — 코치가 그 자리에서 기록하고,
잔여는 기록의 합계로 계산되고, 회원은 자기 폰에서 직접 확인한다.

## 사용자 3종

| 사용자 | 접속 | 로그인 |
|---|---|---|
| 관리자 (대표·실장) | 데스크톱 웹 | 이메일 + 비밀번호 🔵 |
| 코치 | 모바일 웹 | 이메일 + 비밀번호 🔵 |
| 회원 | 모바일 웹 (PWA) | 초대링크 → 장기 세션 🔵 |

# 2. 핵심 개념 — 인터뷰에서 도출된 순서대로

## 2-1. 상품: 차이는 데이터로 🟢

실제 가격표 분석 결과, 가격을 가르는 축은 **인원(1:1/1:2/1:3) × 빈도(주1/2/3회) ×
요일(평일/주말) × 길이(20/30/60분) × 기간**이다. 전부 상품 속성으로 표현한다.

- **쿠폰 레슨 = 상품 한 줄.** 토글·설정·코드 분기 없음. 상품을 안 만들면 그 센터엔 없는 것
- 평일/주말 = 상품 두 개
- 레슨 길이는 센터마다 다르다(20/30/60) → 숫자 컬럼, enum 아님
- 스케줄은 상품을 참조하지 않고 `duration_minutes`를 직접 갖는다 (2026-08-22 결정)

## 2-2. 주 2회 = 시간대 2개, 보통 다른 요일 🟢

하나의 수업권을 여러 요일 스케줄이 공유한다. "정기 이용 관계"가 요일보다 큰 단위라는 근거.

## 2-3. 돈: 시스템 밖에서 오간다 🟢

계좌이체(대부분) + 현장 카드. **입금 확인은 원장이 통장을 직접 본다.**
→ PG(온라인 결제) 연동 없음. 시스템의 역할 = "원장이 확인했다"는 사실의 기록 (결제 승인).

## 2-4. 원장(Ledger): 잔여는 저장하지 않는다 🟢

> "저 3회가 아니라 4회 남았을 텐데요?" 에 답하려면 **숫자가 아니라 날짜별 기록**이 필요하다.
> — 인터뷰 질문 6에서 본인이 직접 도출

잔여를 바꾸는 **모든 사건**(발급/출석/노쇼/복구/조정/외상/정산)을 기록하고, 잔여 = 합계.
부수 효과: 코치가 그 자리에서 기록하니 **수기 장부 → 엑셀 옮기기가 소멸**한다.

## 2-5. 결번 5종과 차감 정책 🟢

| 상태 | 차감 | 정책 주체 |
|---|---|---|
| 출석 | −1 | |
| 사전 취소 | ✕ | |
| 늦은 취소 | ○ | **기준 시간 = 센터 설정** (예: 24시간 전) |
| 노쇼 | ○ | **차감 여부 = 센터 설정** |
| 휴강 (코치·센터 사유) | ✕ | + 원장이 연락하고 보강을 잡는다 |

늦은 취소와 노쇼는 차감이 같아도 **따로 센다** — 연락하는 회원과 안 하는 회원은 다르다.

## 2-6. 빈 시간: 계산하고 저장하지 않는다 🟢

```
빈 시간 = 코치 근무시간 − 이미 잡힌 레슨 − 닫은 구간
```

보강과 쿠폰 회원의 셀프 예약이 같은 메커니즘을 쓴다.

## 2-7. 잔여 임박 알림 + 회원 응답 ⭐ 신규

대면으로 "그만할게요"를 말하기 어려운 회원을 위해:

```
잔여 1회 도달 (시점 = 센터 설정) → 회원에게 알림
→ 회원이 버튼으로 응답: [연장할게요] [그만할게요] [몇 달 쉴게요]
→ 응답이 관리자 처리 큐에 도착 → 원장은 보고 움직인다
```

v1.5에는 알림만 있었다. **회원 응답 버튼과 그 응답의 큐 연동이 신규.**
코치 화면의 잔여 표시(2-11)와 양방향으로 만난다 — 앱으로도, 코치 입으로도.

## 2-8. 유예(Grace): 잔여 0부터 7일 🟢

```
잔여 0 ══ 유예 (기본 7일, 센터 설정) ══╗
  · 자리 보호 (대기자 진입 불가)        ║
  · 레슨 계속 가능 → 외상으로 기록      ║
  입금 확인 → 새 수업권 + 외상 정산    유예 만료 → 자리 개방
```

- **외상은 원장(ledger)이 공짜로 푼다**: 옛 수업권에 `외상 출석 −1`, 새 수업권 발급 시
  `외상 정산 −N` → "8회 재등록, 외상 1회 정산 — 사용 가능 7회"
- 원장이 봐주고 싶으면 유예를 수동 연장 — 기본 규칙은 시스템, 예외는 사람

## 2-9. 홀드(일시정지) 🔵 정책 변경

돈은 냈는데 못 오는 회원(≠유예). 효과: **레슨 생성 중지 · 자리 유지 · 유효기간 연장.**
홀드 중 그 시간은 자동으로 빈 시간이 되어 1회성 예약(보강·쿠폰)에 열린다.

| | 1:1 정기 | 1:2 이상 정기 |
|---|---|---|
| 회원 셀프 홀드 (앱 버튼) | ○ | **✕ (버튼 없음)** |
| 관리자가 걸어주기 | ○ | ○ (재량 — 전화로 상의 후) |

**근거**: 2인 홀드는 남는 사람·가격 조율이 필요한 "대화가 필요한 사건"이라 관리자 경로로
보낸다. 메커니즘은 하나(정기등록의 상태), 차이는 셀프 서비스 범위뿐. 되돌리기 쉬운 결정.

**홀드가 사는 곳**: 스케줄(2인이 같이 멈춤 ✕), 배정 줄(주2회 중복 ✕), 수업권(재등록 시
증발 ✕), 회원(쿠폰까지 멈춤 ✕)을 소거하고 → **정기 등록(recurring_enrollment)**. 유예도 여기 산다.

## 2-10. 2인 레슨의 한 명 이탈 🟢

- 한 명 탈퇴 → 그 사람 배정만 해제, 남은 1명은 자기 수업권으로 계속 (스케줄 유지)
- 남은 사람이 2인 단가로 1:1을 받는 어색함 → **다음 재등록부터 1:1 상품으로 교체**
  (기존 수업권 스냅샷 불변). 그 사이 차액은 원장 재량
- 어뷰징 최대치 = 남은 회차 × 차액으로 **유계(bounded)**, 모든 관문에 원장이 있어
  시스템은 처리 큐에 "2인 스케줄에 활성 1명" 노출만 하면 된다

## 2-11. 출석: 수동이 신뢰 경로, QR은 단축키 🟢

```
코치 화면 오늘 목록: [출석] [취소] [노쇼]   ← 기본. 누구든(오할머니 포함) 처리 가능
QR: 회원이 제시(짧은 만료의 일회용) + 코치가 스캔 = [출석] 자동 탭
스캔 순간 코치 화면: "김서연 출석 — 오늘 7/8회 · 잔여 1회"  ← 재등록 대화 유도
```

노쇼는 안 온 사람이라 QR을 못 찍는다 → 결번 처리는 어차피 수동 → **수동을 먼저 만든다.**

## 2-12. Materializer: 규칙 → 실물 레슨 🟢

"매주 화 20시"는 규칙일 뿐, 출석을 적으려면 날짜별 레슨 기록이 필요하다.

- **당일 생성은 이중 예약 사고를 만든다** — 미생성 고정 슬롯을 빈 시간으로 오인해 보강 예약
- 규칙: **생성 범위 > 예약 가능 범위.** 예약 범위 최대 60일 → rolling 90일 유지, 매일 채움
- 구현 시 주의: 배치가 두 번 돌아도 같은 날 레슨이 2개 생기지 않게 (규칙+날짜 유니크)

## 2-13. 계정과 연결 🔵 대폭 변경

**관리자·직원**: 이메일 + 비밀번호. 매일 쓰니 안 까먹고, 재설정은 이메일(무료).
직원 계정은 대표가 추가 → 이메일로 비밀번호 설정 링크. (v1.5: 전원 SMS OTP였음)

**회원**: 계정을 만들지 않는다. 원장이 등록(이름+연락처 **필수**)하면 회원별 **일회용
초대링크** 생성 → 원장이 카톡·문자로 전달(발송 인프라 불필요, 비용 0) →

```
첫 방문:  링크 클릭 (코드는 URL 파라미터) → 즉시 연결 + 장기 세션. 코드 소멸
평상시:  PWA 아이콘 탭 → 세션으로 바로 진입. 로그인 화면을 안 봄
재로그인: 폰 교체 등 드문 경우만 — 전화번호 + SMS 인증번호 (회원당 연 1건 수준)
```

- 이름+전화번호 "입력 로그인"은 기각 — 지인 누구나 사칭 가능, 레슨 시간표 = 위치+시간 정보
- ProField식 "연결 승인" 단계 생략 — 원장이 특정 회원에게 직접 보낸 코드라 의도가 이미 확인됨
- 오할머니: 링크를 안 눌러도 완전한 회원 (원장이 계속 관리)
- 윤다리(다중 센터): 같은 번호로 두 센터 연결 → 센터 선택 화면
- account 테이블: email / password_hash / phone_number 전부 nullable, 최소 하나

## 2-14. 알림 채널 🔵

- **웹푸시(PWA) = 기본, 무료** — 공지·잔여 임박·레슨 알림
- SMS = 재로그인 인증 전용 (회원당 연 1건 수준, 개발 중엔 콘솔 mock)
- v1.5의 "문자 API 공용 발신번호" 상시 발송 전제를 축소

# 5. v1.5에서 달라진 것 요약

| 영역 | v1.5 | v2 (이번 결정) |
|---|---|---|
| 관리자 로그인 | SMS OTP | **이메일+비밀번호** |
| 회원 연결 | SMS OTP 활성화 | **일회용 초대링크** (SMS 불필요) |
| 회원 재로그인 | OTP | 장기 세션 + 드문 SMS 인증 |
| 잔여 임박 | 알림만 | **알림 + 회원 응답 버튼 3종 → 큐** |
| 홀드 신청 | 참가자별 (경로 구분 없음) | **1:1 셀프 / 1:2+ 관리자 전용** |
| 알림 채널 | 웹푸시 + 문자 | **웹푸시 중심**, 문자는 인증 전용 |
| 프론트 | React PWA (앱 지향 서술) | **웹(PWA) 명시**, 프론트는 AI 전담 |

핵심 도메인(원장·유예·외상·Materializer·결번 5종·빈 시간 계산·스냅샷)은 전부 유지 —
**인터뷰에서 본인이 같은 결론을 다시 도출했다.**
