# 0. 한 문단 요약

테니스 레슨장은 수기 장부와 엑셀로 돌아간다. 코치가 장부에 출석을 체크하면 누군가 엑셀로 옮기고,
원장은 엑셀을 보고 잔여 횟수를 답한다. **옮기는 사이에 어긋나고, 어긋나면 회원과 말싸움이 난다.**
FORTYALL:DESK는 그 옮기는 작업을 없앤다 — 코치가 그 자리에서 기록하고, 잔여는 기록의 합계로
계산되고, 회원은 자기 폰에서 직접 확인한다. 원장에게는 판단이 필요한 일만 올라온다.

# 1. 등장인물

| 인물 | 역할 | 이 사람이 검증하는 규칙 |
|---|---|---|
| 김대표 | 그린코트테니스 원장. 관리자 + 코치 겸임 | 역할 복수 보유 |
| 박준석 | 코치 | 출석 처리, 휴강 |
| 김혜원 | 정기 회원 (주 1회), 웹 사용 | 기본 사이클 |
| 김서연 | 정기 회원 **주 2회 (화·목)**, 6주 출장 예정 | 수업권 공유, 홀드 |
| 김상진·김아들 | **부자 2인 레슨**, 토 11시 한 슬롯 공유 | 참가자별 출석·홀드 |
| 윤다리 | A센터 정기 + B센터 쿠폰 회원 | 다중 센터, 테넌트 격리 |
| 오할머니 | 웹을 안 쓰는 회원 | 오프라인 회원 완전 지원 |

# 2. 사용자와 화면

| 사용자 | 기기 | 화면 원칙 |
|---|---|---|
| 관리자 (대표·실장) | **데스크톱** | 정보 밀도 높게. 처리 큐가 홈 |
| 코치 | **모바일 웹** | 오늘 목록 중심. 엄지로 닿는 큰 버튼 |
| 회원 | **모바일 웹 (PWA)** | 잔여·다음 레슨·QR. 홈 화면에 설치, 웹푸시 수신 |

네이티브 앱은 만들지 않는다. 설치 문턱 없이 링크로 진입하고, PWA로 푸시를 받는다.

# 3. 계정 · 로그인 · 연결

## 3.1 관리자·직원 — 이메일 + 비밀번호

- 대표: 센터 셀프 가입 시 이메일·비밀번호 설정. 센터와 관리자 멤버십이 함께 생성된다
- 직원(실장·코치): **대표가 추가한다** — 이름·이메일·역할 입력 → 그 이메일로 비밀번호 설정 링크
- 왜 이메일인가: 매일 로그인하는 사람은 비밀번호를 안 까먹고, 재설정도 이메일이라 무료다
- 이 시스템에서 계정은 항상 **위에서 만들어주고 본인은 활성화만 한다** (직원 = 비밀번호 설정, 회원 = 링크 클릭)

## 3.2 회원 — 초대링크, 계정을 만들지 않는다

```
원장: 회원 등록 (이름 + 연락처, 둘 다 필수)
   → 회원별 일회용 초대링크 자동 생성 (코드는 URL에 포함)
   → 원장이 카톡·문자로 직접 전달              ← 발송 인프라 불필요, 비용 0

회원: 링크 클릭 → 즉시 연결 + 장기 로그인      ← 입력할 것 없음. 코드는 이 순간 소멸
평상시: PWA 아이콘 탭 → 바로 내 페이지          ← 로그인 화면을 안 봄
재로그인(폰 교체 등): 전화번호 + SMS 인증번호    ← 회원당 연 1건 수준
```

- **이름+전화번호 "입력 로그인"은 채택하지 않는다.** 지인 누구나 사칭 가능하고,
  레슨 시간표는 위치+시간 정보라 유출 시 위험이 실재한다
- 연결 승인 단계 없음 — 원장이 특정 회원에게 직접 보낸 코드라 의도가 이미 확인됨
- 오할머니: 링크를 안 눌러도 완전한 회원. 원장이 계속 관리한다
- 윤다리: 같은 번호가 두 센터에 등록 → 접속 시 센터 선택 화면

## 3.3 연락처 두 개는 별개다

- `로그인 번호` (계정): 본인만 변경
- `센터 연락처` (멤버십): 해당 센터 관리자가 수정 — 알림 발송용
- 합치면 A센터 관리자의 수정이 B센터 로그인까지 바꾼다 (테넌트 경계 침범)

# 4. 상품과 가격 — 차이는 데이터로

실제 레슨장 가격표를 가르는 축: **인원(1:1/1:2/1:3) × 빈도(주1/2/3회) × 요일(평일/주말) ×
길이(20/30/60분) × 기간(1/3개월)**. 전부 상품 속성이다.

| 속성 | 예 |
|---|---|
| 이름 | "평일 1:1 주2회 (월 8회)" |
| 레슨 길이 | 20 / 30 / 60분 — **숫자. 센터마다 다르다** |
| 인원 | 1 / 2 / 3 |
| 횟수 | 8 |
| 유효기간 | 35일 |
| 가격 | 370,000 |

- **쿠폰 레슨 = 상품 한 줄.** 토글·설정·코드 분기 없음. 상품을 안 만들면 그 센터엔 없는 것
- 평일/주말 가격 차이 = 상품 두 개
- **판매 후 상품을 수정해도 이미 판 수업권의 조건은 불변** (구매 시점 스냅샷). 가격 인상이
  작년 계약을 소급 변경하면 안 된다
- 체험 레슨 = 횟수 1짜리 상품. 특별 취급 없음

# 5. 등록 장면 (신규 회원의 탄생)

```
상담: 배운 적 있나, 실력, 시간대 → 김대표가 상품·가격 설명
   ↓ 하겠다고 하면
등록: 이름 + 연락처 입력 → 시간대 확정 (주 2회면 요일 2개) → 코치 배정
   ↓
결제: 계좌이체 or 현장 카드 → 김대표가 통장 확인 → 시스템에 "결제 확인" 기록
   ↓                                    ※ PG(온라인 결제) 연동 없음 — 돈은 시스템 밖
수업권 발급: 8회, 유효기간 시작
   ↓
초대링크 발송 → 회원 연결 (안 해도 무방)
```

# 6. 수업권과 원장(Ledger) — 이 서비스의 심장

## 6.1 잔여는 저장하지 않는다

> 김서연: "저 3회가 아니라 4회 남았을 텐데요? 지난주 목요일에 안 왔어요."
> 엑셀의 `잔여=3` 숫자로는 답할 수 없다. **날짜별 기록**이 있어야 답한다.

잔여를 바꾸는 **모든 사건**을 기록하고, 잔여 = 기록의 합계.

```
8/01  발급        +8      8/28  노쇼        -1
8/05  화 출석     -1      8/29  노쇼 복구    +1   ← 사정 확인 후
8/07  목 출석     -1      9/02  관리자 조정  -1
                          ──────────────────────
                          잔여 = 합계 = 6
```

- 사건 종류: 발급 / 출석 / 노쇼 / 늦은취소 / 복구 / 조정 / 만료 / 외상 / 정산
- 관리자의 임의 수정도 "조정" 사건으로 남는다 — 장부에 안 남는 변경은 없다
- 부수 효과: 코치가 그 자리에서 기록하니 **수기 장부 → 엑셀 옮기기가 소멸**

## 6.2 잔여 / 확보 / 사용

| | 뜻 |
|---|---|
| 잔여 | 원장 합계 |
| 확보 | 셀프 예약이 미리 잡아둔 횟수 |
| 추가 예약 가능 | 잔여 − 확보 |

**고정 레슨은 확보하지 않는다.** 매주 자동 생성되고 출석 시점에 차감한다. 잔여가 부족해도
고정 레슨은 생성된다 — 유예·외상이 받는다 (9장). 이 비대칭이 재등록 사이클과 맞물린다.

## 6.3 재등록 = 항상 새 수업권

UI에서 "충전"이라 불러도 내부는 새 수업권 발급이다. 40만원에 산 8회와 45만원에 산 8회가
한 수업권에 섞이면 "이 회차는 어느 조건인가"에 답할 수 없다.

# 7. 고정 스케줄과 레슨 생성

## 7.1 구조 — 네 개의 층

| 층 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 고정 스케줄 | 시간 규칙 (매주 화 20:00 · 박준석 · 30분) | 누가 다니는지, 홀드 |
| **정기 등록** | 회원의 정기 이용 관계 (홀드·유예·현재/다음 수업권) | 시간, 요일 |
| 스케줄 배정 | 어느 정기 등록이 어느 스케줄에 참가하나 | — |
| 레슨 | 특정 날짜의 실제 수업 1건 | 규칙 |

- 주 2회 김서연 = 정기 등록 1개 ← 스케줄 배정 2줄 (화, 목)
- 2인 김상진·김아들 = 스케줄 1개 ← 각자의 정기 등록에서 배정 1줄씩
- 1인/2인/주2회/한 명 중단이 **같은 구조**로 표현된다. 특수 케이스 코드가 없다

## 7.2 Materializer — 규칙에서 실물 레슨을 미리 만든다

"매주 화 20시"는 규칙일 뿐이다. 출석·차감·변경을 적으려면 날짜별 레슨 기록이 필요하다.

- **당일 생성은 사고를 만든다**: 다음 주 금요일 레슨이 아직 없으면 그 시간이 "빈 시간"으로
  보이고, 원장이 거기 보강을 잡으면 **이중 예약**이 된다. 시스템이 시킨 사고다
- 규칙: **생성 범위 > 예약 가능 범위.** 셀프 예약이 최대 60일까지 열리므로 rolling 90일 유지
- 매일 배치가 빈 날짜를 채운다. 두 번 돌아도 레슨이 중복 생성되지 않아야 한다 (규칙+날짜 유니크)
- 회원이 개별 이동한 레슨은 재생성이 덮어쓰지 않는다

# 8. 출석과 결번

## 8.1 기록 — 수동이 신뢰 경로, QR은 단축키

```
코치 화면 (오늘 목록):  20:00 김서연  [출석] [취소] [노쇼]   ← 기본. 오할머니도 처리 가능
QR: 회원이 제시 (짧은 만료의 일회용 서명 토큰) + 코치가 스캔 = [출석] 자동
스캔 순간 코치 화면: "김서연 출석 — 오늘 7/8회 · 잔여 1회"   ← 재등록 대화가 자연 발생
```

노쇼는 안 온 사람이라 QR을 못 찍는다 → 결번 처리는 어차피 수동 → 수동을 먼저 만든다.

## 8.2 결번 5종

| 상태 | 차감 | 비고 |
|---|---|---|
| 출석 | −1 | |
| 사전 취소 | ✕ | 회차가 남는 것이 결번 처리의 전부 |
| 늦은 취소 | ○ | **기준 시간 = 센터 설정** (기본 24시간 전) |
| 노쇼 | ○ | **차감 여부 = 센터 설정.** 복구 가능 |
| 휴강 (코치·센터 사유) | ✕ | 원장이 연락 + 보강 |

- 늦은 취소와 노쇼는 차감이 같아도 **따로 센다** — 연락하는 회원과 안 하는 회원은 다르다
- 종료 후 아무 상태가 없는 레슨 = **미처리** → 관리자 큐로. **자동 노쇼 없음** (판단은 사람)
- 사전취소·이동으로 비워진 정기 슬롯은 **그 주에 한해** 빈 시간이 된다

# 9. 재등록 사이클 — 알림 → 응답 → 유예 → 외상

## 9.1 잔여 임박 알림과 회원 응답 ⭐

대면으로 "그만할게요"를 말하기 어려운 회원이 조용히 사라지는 것이 실제 이탈 패턴이다.

```
잔여 1회 도달 (시점 = 센터 설정)
   → 회원에게 푸시: "수업권이 1회 남았어요"
   → 회원 응답 버튼: [연장할게요] [그만할게요] [몇 달 쉴게요]
   → 응답이 관리자 처리 큐에 도착
```

코치 화면의 잔여 표시(8.1)와 양방향 — 앱으로도 오고, 코치 입으로도 나온다.

## 9.2 유예(Grace) — 잔여 0부터 7일

```
잔여 0 ═══════ 유예 (기본 7일, 센터 설정) ═══════╗
        · 자리 보호 — 대기자 진입 불가              ║
        · 레슨 계속 가능 → 외상으로 기록            ║
   입금 확인 → 새 수업권 + 외상 정산          유예 만료 → 자리 개방
```

- 원장이 악역을 안 해도 된다 — "규정상 7일"은 시스템이 말한다. 봐주고 싶으면 수동 연장
- 유예 ≠ 홀드: 유예는 *돈이 안 들어온* 보호 장치, 홀드는 *돈은 냈는데 못 오는* 일시정지

## 9.3 외상(Carry-over) — 원장이 공짜로 푼다

```
[옛 수업권]                        [새 수업권]
8/28 외상 출석  -1  (잔여 -1)       9/02 발급     +8
                                   9/02 외상 정산 -1
                                   ────────────────
                                   사용 가능 7회
```

회원에게: "8회 재등록 완료, 지난달 외상 1회 정산 — 사용 가능 7회". 말싸움 여지가 없다.
유예가 지나도 외상 기록은 남아 있다가 다음 등록 때 정산한다.

# 10. 빈 시간 · 보강 · 셀프 예약

```
빈 시간 = 코치 근무시간 − 이미 잡힌 레슨 − 닫은 구간
```

- **빈 시간 테이블은 없다.** 계산 결과를 저장하면 갱신 누락으로 반드시 어긋난다 —
  수기 장부와 엑셀이 어긋나던 문제가 시스템 안에서 재현되는 것
- 닫은 구간 = 코치가 개인 사정으로 막아둔 시간 (휴강과 다름 — 예약되기 전에 막는 것)
- **보강과 쿠폰 회원의 셀프 예약은 같은 메커니즘** — 빈 시간에 1회짜리 레슨을 넣는 것
- **예약 시작 간격과 레슨 길이는 별개다** — 간격 10분 + 30분 레슨이면 19:00~19:30, 19:10~19:40
  처럼 겹치는 시작점이 생긴다. 예약 가능 판정은 시작 시각 비교가 아니라 **시간 구간 겹침 검사**
- 셀프 예약은 즉시 확정 + 1회 확보. 예약 가능 범위 = 센터 설정 (기본 30일)
- 동시에 두 명이 같은 슬롯을 누르면 한 명만 성공해야 한다 (구현: 동시성 제어)

# 11. 홀드 (일시정지)

효과: **레슨 생성 중지 · 자리 유지 · 유효기간을 홀드 일수만큼 연장.**
홀드 중 그 시간은 자동으로 빈 시간이 되어 1회성 예약에 열린다 (7.2의 생성 중지 + 10장의 계산).

| | 1:1 정기 | 1:2 이상 정기 |
|---|---|---|
| 회원 셀프 홀드 (버튼) | ○ | **✕ — 버튼 없음** |
| 관리자가 걸어주기 | ○ | ○ (전화로 상의 후 재량) |

- 2인 홀드는 남는 사람·가격 조율이 필요한 **대화가 필요한 사건**이라 관리자 경로로 보낸다
- 메커니즘은 하나 (정기 등록의 상태). 차이는 셀프 서비스 범위뿐 — 되돌리기 쉬운 결정
- 홀드가 정기 등록에 사는 이유 (소거법): 스케줄이면 2인이 같이 멈추고, 배정 줄이면 주 2회가
  중복되고, 수업권이면 재등록 때 증발하고, 회원이면 쿠폰까지 멈춘다

# 12. 2인 레슨 규칙

- 한 슬롯 공유, **각자 회원 · 각자 수업권 · 각자 출석 상태** (아버지 출석, 아들 노쇼 가능)
- 한 명 탈퇴 → 그 사람 배정만 해제. 남은 1명은 자기 수업권으로 계속, 스케줄 유지
- 남은 사람이 2인 단가로 1:1을 받는 어색함 → **다음 재등록부터 1:1 상품으로 교체.**
  기존 수업권 스냅샷은 불변, 그 사이 차액은 원장 재량
- 어뷰징 최대치 = 남은 회차 × 차액으로 **유계**. 모든 관문(등록·승인·재등록)에 원장이 서
  있으므로 시스템은 큐에 "2인 스케줄에 활성 1명"을 노출만 하면 된다

# 13. 관리자 처리 큐

원칙: **자동으로 처리되는 건 큐에 안 띄운다. 사람 판단이 필요한 것만 모은다.**

| 큐 항목 | 발생 |
|---|---|
| 입금 확인 대기 | 회원이 "연장할게요" 응답 / 신규 등록 |
| 회원 응답 | "그만할게요" / "몇 달 쉴게요" ⭐ |
| 외상 발생 | 유예 중 출석 |
| 유예 임박·만료 | 자동 카운트다운 |
| 미처리 레슨 | 종료 후 상태 없음 |
| 2인 스케줄에 활성 1명 | 한 명 탈퇴·홀드 |
| 코치 휴강 신청 | 코치 발신 |

# 14. 알림

| 채널 | 용도 | 비용 |
|---|---|---|
| **웹푸시 (PWA)** | 공지 · 잔여 임박 · 유예 · 레슨 변경 — **기본 채널** | 0 |

# 16. 스코프 아웃

**만들지 않는다**: PG 결제 · 알림톡 · 인앱 1:1 메시지 · 후기·평점 · 코트 자원 관리 · 기간권 ·
소셜 로그인(카카오는 후순위 후보) · 지도에서 센터 찾기(마켓플레이스 방향 아님) · 자동 노쇼

# 17. v1.5 → v2 결정 이력

| 영역 | v1.5 | v2 | 이유 |
|---|---|---|---|
| 관리자 로그인 | SMS OTP | 이메일+비밀번호 | 매일 쓰는 사람은 안 까먹음, 재설정 무료 |
| 회원 연결 | OTP 활성화 | 일회용 초대링크 | SMS 인프라 불필요, 원장 카톡이 전달 채널 |
| 회원 재로그인 | OTP | 장기 세션 + 드문 SMS | 사용은 잦고 로그인은 드물다 |
| 잔여 임박 | 알림만 | 알림 + 응답 버튼 3종 → 큐 | 대면으로 말 못 하는 회원의 이탈 방지 ⭐ |
| 홀드 신청 | 경로 구분 없음 | 1:1 셀프 / 1:2+ 관리자 | 2인 홀드는 대화가 필요한 사건 |
| 알림 | 웹푸시+문자 병행 | 웹푸시 중심 | 비용 구조 |
| 스케줄→상품 참조 | product_id | duration_minutes 직접 보유 | "자리가 10회권 전용인가"는 말이 안 됨 |
| 네이밍 | 기획 용어 그대로 | `docs/네이밍_규칙.md` | transaction 혼동 등 (2026-08-22) |

핵심 도메인 — 원장(6장) · 결번 5종(8장) · 빈 시간 계산(10장) · 유예·외상(9장) ·
Materializer(7장) · 스냅샷(4장) · 2인 규칙(12장) — 은 v1.5와 동일하며,
재수립 인터뷰에서 **개발자 본인이 같은 결론을 다시 도출**했다.
