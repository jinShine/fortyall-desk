# [과제 1] 엔티티 후보 뽑기

> 먼저 혼자 뽑은 다음에 비교해야 실력이 늡니다.

## 읽을 범위

`docs/기획서_Master_v1.5.md` 중 **4장(핵심 도메인 모델)** 과 **부록 용어집**.
여유 되면 3장(사용자 정의)까지.

## 판별 질문 (이 3개를 통과하면 엔티티)

1. **목록으로 관리해야 하나?** ("회원 목록을 보여줘"가 말이 되나)
2. **각각을 따로 식별해야 하나?** (2번 회원과 5번 회원을 구별할 일이 있나)
3. **독립적으로 생기고 사라지나?** (다른 것 없이도 혼자 존재할 수 있나)

## 작성 예시

| 후보     | 엔티티? | 왜 그렇게 판단했나                                                                        |
| -------- | :-----: | ----------------------------------------------------------------------------------------- |
| 센터     |   ⭕    | 센터 목록이 필요하고, 각 센터를 구별해야 하며(테넌트 격리 단위), 독립적으로 생성·해지된다 |
| 센터명   |   ❌    | 센터에 딸린 값 하나일 뿐. "센터명 목록"은 의미가 없다 → **속성**                          |
| 영업시간 |   ❓    | 센터의 속성 같지만 요일마다 다르다(7개). 값 1개가 아니면 속성으로 안 들어간다 → 판단 보류 |

## 내 답

| 후보 | 엔티티? | 왜 그렇게 판단했나 |
| ---- | :-----: | ------------------ |
|      |         |                    |

| 후보           | 판단 근거                                                                                                                                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **회원**       | 회원은 여러 명 존재하고 각각 구분해야 함. 이름·연락처·상태 등의 속성을 가지며 가입/탈퇴 같은 생명주기가 있고 다른 데이터와 연결됨.                                                                              |
| **수업권**     | 회원마다 여러 수업권을 가질 수 있고 각각 잔여횟수·상태·유효기간 등이 다름. 발급→활성→소진/만료라는 생명주기도 명확함.                                                                                           |
| **횟수변경**   | 하나의 수업권에서 출석 -1, 복구 +1, 만료 -N 등 여러 기록이 발생함. 변경량·변경종류·발생일 등의 속성을 독립적으로 기록해야 하므로 엔티티로 볼 수 있음. 단, 한번 기록되면 보통 변경되지 않으므로 생명주기는 약함. |
| **결제**       | 결제 건이 여러 개 발생하고 각각 금액·결제수단·승인여부·승인일 등을 가짐. 결제 건별 조회가 필요하기 때문에 독립 엔티티로 보는 것이 자연스러움.                                                                   |
| **레슨 상품**  | 20분 10회권, 체험 1회권 등 여러 상품이 존재함. 각각 가격·횟수·유효기간·인원·설명 등의 속성을 가지고 판매중/중단 등의 상태도 가질 수 있음.                                                                       |
| **고정스케줄** | 화요일 20시, 목요일 19시처럼 여러 규칙이 존재하고 각각 코치·요일·시간·길이 등을 가짐. 생성되고 변경되거나 종료될 수도 있으므로 독립 엔티티임.                                                                   |
| **정기등록**   | 회원별로 정기 이용 관계가 만들어짐. 현재 수업권·다음 수업권·Grace·Hold·상태 등을 가지고 등록→이용→홀드→종료처럼 생명주기가 있음.                                                                                |
| **슬롯**       | 문서의 슬롯은 특정 객체라기보다 `시작~종료 시간 구간`과 예약 가능 여부를 표현하는 개념에 가까움. 특히 빈 시간은 다른 데이터에서 계산되므로 별도 ID를 가진 독립 엔티티라고 보기 어려움.                          |
| **실력 등급**  | `NTRP 3.0`, `3.5` 같은 값 자체는 다른 대상을 설명하는 값임. 각각의 3.0에 ID나 생명주기가 필요한 것이 아니므로 엔티티가 아니라 속성에 가까움.                                                                    |
